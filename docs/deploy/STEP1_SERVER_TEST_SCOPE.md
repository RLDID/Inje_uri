# Inje_uri 서버 시험 가동 범위 정의

## 1. 현재 단계

현재 단계는 정식 운영 배포가 아니라 서버 내부 시험 가동 준비 단계다.

목표는 Inje_uri 프로젝트가 Docker 기반으로 빌드되고, 테스트용 DB와 함께 서버 내부에서 실행 가능한지 확인하는 것이다.

## 2. 현재 서버 상태

기존 oiso / judge 계열 서비스는 정리했다.

현재 의미 있는 포트는 다음과 같다.

- 25600: SSH 접속

- 80: nginx 기본 HTTP

현재 단계에서는 443 HTTPS를 사용하지 않는다.

현재 단계에서는 nginx를 Inje_uri 앱으로 연결하지 않는다.

## 3. 이번 브랜치에서 할 일

브랜치명:

- chore/deploy-prep

이번 브랜치에서 하는 일:

1. Dockerfile 작성

2. .dockerignore 작성

3. 서버 시험용 docker-compose 파일 작성

4. 테스트용 PostgreSQL 컨테이너 정의

5. Inje_uri 앱 컨테이너 정의

6. 로컬에서 Docker 빌드 가능 여부 확인

7. GitHub에 push

8. 서버에서 pull

9. 서버 내부에서만 시험 실행

## 4. 이번 단계의 성공 기준

이번 단계는 기능 완성 여부가 아니라 실행 가능성 확인이 목적이다.

성공 기준:

1. Docker 이미지가 빌드된다.

2. 앱 컨테이너가 실행된다.

3. 테스트용 PostgreSQL 컨테이너가 실행된다.

4. 앱이 DATABASE_URL을 통해 테스트 DB에 접근할 수 있다.

5. 서버 내부에서 앱 응답을 확인할 수 있다.

6. 치명적인 시작 오류 없이 로그가 나온다.

## 5. 이번 단계에서 하지 않을 일

이번 단계에서는 아래 작업을 하지 않는다.

1. 운영 도메인 연결

2. nginx를 Inje_uri로 연결

3. HTTPS / SSL 설정

4. 운영 DB 사용

5. 실제 사용자 공개

6. GitHub Actions 자동배포

7. 운영용 migration 확정

8. 실제 운영 데이터 입력

## 6. DB 전략

이번 단계에서는 운영 DB를 사용하지 않는다.

테스트용 PostgreSQL 컨테이너를 사용한다.

Docker Compose 내부에서는 앱 컨테이너가 DB에 접속할 때 localhost가 아니라 DB 서비스명을 사용한다.

예시:

    DATABASE_URL=postgresql://postgres:postgres@db:5432/injeuri?schema=public

주의:

- 이 값은 시험용 예시다.

- 운영 비밀번호가 아니다.

- 실제 운영용 DB 정보는 Git에 올리지 않는다.



## 7. 환경변수 원칙



환경변수는 코드 밖에서 주는 설정값이다.



현재 최소 필요 환경변수:



- DATABASE_URL



추후 API 통합 과정에서 추가될 수 있는 환경변수:



- 인증/세션 비밀키

- 이메일 인증 관련 값

- 외부 API 키

- 관리자용 내부 토큰



주의:



- .env 파일은 Git에 올리지 않는다.

- .env.example에는 예시값만 둔다.



## 8. 포트 전략



현재 시험 단계 권장 포트:



- 앱 컨테이너 내부 포트: 3000

- PostgreSQL 컨테이너 내부 포트: 5432

- 외부 공개 포트: 사용하지 않음

- nginx 연결: 하지 않음



서버 내부 테스트가 필요할 경우에만 127.0.0.1:3000 형태로 제한적으로 바인딩한다.



## 9. 멈춰야 하는 조건



아래 상황이 나오면 다음 단계로 강행하지 않는다.



1. Docker 이미지 빌드 실패

2. 앱 컨테이너가 즉시 종료됨

3. DATABASE_URL 오류로 DB 연결 실패

4. Prisma migration 실행 중 파괴적 변경 우려

5. 환경변수 목록이 불명확함

6. API 미완성 문제가 아니라 앱 시작 자체가 불가능함



## 10. 결론



현재 단계는 정식 배포가 아니다.



현재 목표는 Inje_uri 프로젝트를 Docker 기반으로 포장하고, 테스트용 DB와 함께 내부 시험 가동이 가능한지 확인하는 것이다.



운영 공개는 API, DB, 환경변수, nginx, 도메인, SSL 전략이 정리된 뒤 별도 단계에서 진행한다.
